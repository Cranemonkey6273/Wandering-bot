# Google Play Production Access Answers

These answers are written to match the app as it actually exists. Adjust only details that are factually different when the Play Console form appears.

## 1. How did you recruit users for your closed test?

We used a paid testing provider and invited DayZ server owners and community administrators from our target audience. This gave us both structured device testing and feedback from people familiar with Discord communities, Nitrado server administration and DayZ server-management workflows.

## 2. How easy was it to recruit testers?

Choose the answer that matches the Play Console options. "Easy" is reasonable if the paid testing group and community testers joined without repeated recruitment attempts.

## 3. Describe the engagement you received from testers.

Testers used the app across different devices and Android configurations, checked the main mobile workflows and supplied a written usability report. Their feedback concentrated on discoverability, first-use guidance, login expectations and easier access to ratings and support. The report did not identify a critical crash or core functional failure during the closed test.

## 4. Summarise the feedback and explain how it was collected.

Feedback was collected through the closed-testing provider, written reports and direct communication with target users. Testers recommended clearer Play Store wording, a first-use walkthrough, an in-app feedback and rating route, and clearer explanations of security and server-management features. They also suggested Google Sign-In and push notifications as possible future enhancements.

## 5. Who is the intended audience?

The app is intended for adult DayZ server owners, administrators and community managers who use Wandering Bot to manage connected DayZ and Discord communities. It is designed for users who need mobile access to server feeds, events, economy controls, operational controls and DayZ file guidance.

## 6. How does the app provide value?

Wandering Bot gives server administrators a focused mobile view of the tools and data already protected by the Wandering Bot backend. Users can switch between configured servers, review recent activity, manage supported events and economy settings, use guarded server controls and learn how common DayZ files work together. Sensitive credentials and live file operations remain on the backend rather than being stored in the app.

## 7. How many installs do you expect in the first year?

Select the range supported by your real launch plan and audience size. Do not choose a larger range only because it sounds impressive. A conservative range is easier to justify for a specialist DayZ server-administration app.

## 8. What changes did you make based on the closed test?

We expanded the Play Store description and feature wording, added a first-use mobile walkthrough, added an in-app dashboard review and Google Play rating entry, and made support and security information easier to find. We also retained the existing DayZ field guide, which explains linked XML and JSON files, backup steps, validation and restart requirements.

Google Sign-In and push notifications were recorded as future improvements because they require separate authentication and notification infrastructure. They were not claimed as completed features.

## 9. How did you decide the app was ready for production?

The closed test covered the main mobile workflows across multiple devices and Android configurations, and the supplied report did not identify critical crashes or core functional failures. We reviewed the recommendations, addressed the launch-readiness improvements that were within the current release scope, and kept protected actions on the existing authenticated backend. We will continue monitoring feedback and releasing maintenance updates after production access.

## 10. What did you do differently this time?

We used structured external testing alongside feedback from the app's actual target audience. We focused on first-use clarity, truthful store wording, easier feedback and support access, and clear explanations of how server credentials and live changes are protected. We also separated launch requirements from future enhancements so the production submission accurately describes the released build.
